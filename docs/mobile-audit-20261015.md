## 检查方法与范围

- 使用 Chromium 的移动设备模拟，开启触摸与移动视口；尺寸以 CSS 像素记录。
- 首屏检查：320×568、390×844、430×932、844×390，共 28 组页面/尺寸组合。
- 补充 360×640 的关于我们与加入流程检查。
- 在 320×568 与 390×844 下，逐一点击 20 个主章节/功能标签，共 40 次切换。
- 关于我们进一步检查故事、价值观、使命、8 个发展节点；发展历程另用屏幕坐标直接触摸点击复核，排除了自动化工具滚动带来的误判。
- 测试文件为浏览器内构造的 PDF，未发送文件或提交申请。
- 没有使用真实手机，未覆盖 Safari/WebKit、Android 系统文件选择器、真实软键盘和低性能设备。

## 结论

常见竖屏尺寸下主要功能能使用，未发现整页横向溢出或可见图片加载失败。主要风险来自分页继续强制单屏：屏幕变短后，固定头部、标题、标签和页脚占据大部分高度，正文被压缩或裁切。横屏需要优先处理，其次是小屏阅读与触摸区域。

P1 表示影响内容阅读或操作，应优先处理；P2 表示体验问题；P3 表示边界留白问题。

### P1-01：横屏下多个分页正文或操作不可达

复现：844×390，直接进入对应分页，等待入场动画结束。

- 次元坞：正文与界面图片区几乎折叠，只剩下方六个功能标签，产品展示失去主要内容。
- 核心团队：成员卡片超出内容框，标题与姓名挤在一起；介绍按钮和成员翻页控件被裁切。

- 联系合作：邮箱与复制按钮落在屏幕底部之外，联系方式区域高度约 24px。

这些页面在增强模式下将 body 设置为 overflow:hidden，舞台及内容框继续裁切；用户不能依靠正常页面滚动找回被遮挡的操作。
