# 性能优化与部署记录

日期：2026-10-15。对比基线：`81e1843`。本轮保留原生静态站点实现，目标是减少首轮下载、请求数和不可见动画的工作量。

## 改动范围

- **无损图片**：Logo、六张产品截图和音乐字标新增全尺寸 WebP，原始 PNG 继续保留。8 张图片逐一验证了尺寸及解码后 RGBA 像素完全相同，没有缩图或有损压缩。
- **截图按需加载**：首个产品截图保持高优先级，其他截图延迟加载；悬停或键盘聚焦标签时预读对应图片。停留 1.8 秒后只预读下一张；Save-Data 或 2G 下跳过这些推测性图片请求。直接打开产品页时提前应用既有增强样式类，防止无脚本降级布局在初始化前触发所有截图请求；禁用 JavaScript 的完整内容展示仍保留。
- **分区脚本**：首页初始只载入 5 个共享/首页脚本，独立分区页面另载入当前分区脚本。导航先等待目标 HTML 与模块就绪，再执行原有的内容插入、布局测量和入场动画；已加载模块复用，加载失败沿用整页导航降级。
- **空闲工作量**：自定义光标沿用 `.22` 跟随系数，移动差值小于 `.001px` 时停止帧循环，下次移动继续；后台暂停。联系页在移动布局隐藏装饰图形时暂停对应动画，显示后继续；可见文字和装饰的原有动效参数保留。
- **生产发布**：开发资源使用内容版本查询参数；`dist/` 使用 SHA-256 前 12 位组成的内容哈希文件名。14 份 CSS 保持原有级联顺序合并为一份，未重写样式规则。文本资源生成 gzip 和 Brotli 副本。

同为未压缩条件，产品页首轮体积下降 **65.7%**，首页下降 **20.4%**。产品页在测量时只请求当前一张截图；停留后会额外预读下一张，切换所有章节后仍会下载全部原尺寸图片。这是按展示时机分摊下载，并非删除页面内容。

## 构建检查

```bash
node scripts/build.js --production
node scripts/check-build.js
```

当前校验结果：12 个 HTML、363 个本地引用、45 个带哈希资源（含合并样式）、26 对 gzip/Brotli 文件。检查会验证模板展开、本地引用存在、文件名与内容哈希匹配，以及两种压缩副本均能解压为原始文件。

另外检查了 22 个 JavaScript 文件和图片脚本语法、单页构建、旧入口兼容、完整生产构建以及连续两次生产输出的一致性。`--production` 与 `--only` 不能混用，避免发布包混入过期页面。

图片替换后运行 `python scripts/optimize-images.py` 重新生成无损副本，再完整构建。此可选素材步骤需要 Pillow；日常 Node 构建与资源检查没有 npm 依赖。

## 部署步骤

1. 在 `src/content/pages.js` 填写真实 `SITE_URL` 后重新构建，生成 canonical、Open Graph 地址和 sitemap；当前为空，没有擅自设置域名。
2. 只发布 `dist/` 的内容，将 `deploy/nginx.conf` 模板纳入 Nginx 的 `http {}`，配置真实目录、域名与 HTTPS。
3. 模板默认启用动态 gzip。服务器具备对应模块时可开启 `gzip_static` 使用 `.gz`；Brotli 需要额外模块与配置，生成 `.br` 不等于服务器已经启用 Brotli。
4. HTML 使用 `no-cache`，带哈希资源使用一年 `immutable` 缓存；其他资源使用短缓存。更新内容时重新构建，资源 URL 随内容变化。
5. 先上传资源，再切换 HTML；建议使用版本目录和原子切换。让上一版本的哈希资源在新发布目录里仍可访问，避免旧标签页随后加载分区时产生 404。
6. 上线环境执行 `nginx -t`，成功后重载，再检查响应头、压缩、404 行为以及全部六个分区。

没有提供生产服务器访问方式，本轮没有修改服务器或执行真实部署。Nginx 模板尚未在目标服务器运行 `nginx -t`；没有公网压力测试、真实低端设备测试或移动 Safari 验证。完整高分辨率图片仍有解码内存开销；按用户要求保留画质与特效，未裁减可见动画或强行降低图片分辨率。
